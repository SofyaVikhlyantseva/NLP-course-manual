# Механизмы внимания и трансформеры
В современном машинном обучении, особенно в области NLP, одной из ключевых проблем является качественное моделирование контекстных зависимостей в последовательностях данных. Традиционные подходы, такие как рекуррентные и сверточные нейронные сети, сталкиваются с ограничениями при работе с длинными последовательностями из-за трудностей с запоминанием дальних зависимостей и вычислительной неэффективностью при параллельной обработке.

**Механизм внимания** решает эту проблему, позволяя моделям динамически фокусироваться на важных частях данных, независимо от их положения. Он вычисляет взвешенные связи между всеми элементами последовательности.

**Трансформеры** — архитектура, построенная на основе внимания без рекуррентных или сверточных слоев. Они обеспечивают:

 - параллельную обработку последовательностей;
 - эффективное моделирование контекста;
 - масштабируемость для больших данных.

Эта архитектура легла в основу современных языковых моделей и стала стандартом для задач перевода, классификации и генерации текста.

Мы разберём принципы работы механизма внимания, устройство трансформеров и их применение в различных типах моделей.

# Механизм внимания: математическое описание

Хотя существует различные виды механизмов внимания, адаптированные под разные задачи, каждый из них следует общей схеме вычисления внимания как взвешенной суммы значений, где веса определяются на основе совместимости между запросами и ключами.

## Компоненты механизма внимания

 - **Запросы (Q)** — векторы, представляющие текущий элемент, для которого вычисляется внимание.
 - **Ключи (K)** — векторы, с которыми сравнивается запрос. Каждый ключ соответствует элементу входной последовательности. Сравнивая запрос с каждым ключом, модель определяет, насколько релевантен каждый элемент входной последовательности для текущего запроса
 - **Значения (V)** — векторы, из которых формируется итоговый вывод внимания.

*Можно привести такую аналогию* 
> Каждая книга имеет:
> 
>  - K — аннотацию, где кратко описано содержание;
>  - V — текст книги;
>  - Q — описание темы, которую вы ищете.
> 
> Механика:
> 
>  1. Вы читаете аннотации всех книг (K) и сравниваете с темой поиска (Q).
>  2. Книги с ближе подходящими аннотациями получают больший вес.
>  3. Вы читаете фрагменты содержания (V) этих книг, пропорционально их важности, и "смешиваете" эту информацию.
>  4. Получаете итог — комбинированное знание из релевантных книг.

## Вычисление весов

 1. Для каждого запроса **q** вычисляется степень соответствия с каждым ключом **k** — обычно с помощью скалярного произведения. Чтобы стабилизировать градиенты во время обучения, результат скалярного произведения масштабируется (делится) на корень из размерности вектора ключа:
    
    $$
    e_{q,i} = \frac{q \cdot k_i}{\sqrt{d_k}}
    $$
    
    Результат показывает, насколько запрос "совместим" с каждым ключом.
 
 2. Значения передаются в функцию softmax для генерации весов — вероятностного распределения внимания (в сумме они дают 1): 
    
    $$ 
    \alpha_i = \mathrm{softmax}(e_{q,i})
    $$
    
    Чем выше вес, тем больше внимания уделяется соответствующему значению **v**.

Каждый вектор значений **v** взвешивается соответствующим коэффициентом из softmax, и результаты складываются. Это даёт итоговый вектор внимания:

$$
\text{Attention}(q, K, V) = \sum_{i} \alpha_{q,i}\, v_{k_i}
$$

# Self-attention

**Self-Attention** — это разновидность механизма внимания, при котором запросы, ключи и значения формируются из **одной и той же последовательности**. 

Иначе говоря, для каждого элемента строится своё уникальное окружение — модель смотрит на все остальные токены в последовательности и решает, на какие из них стоит опереться для представления текущего токена.

Принцип работы self-attention строится следующим образом:

 1. Каждый входной вектор умножается на три обучаемые матрицы весов **W(Q)**, **W(K)**, **W(V)** для генерации векторов **Q**, **K**, **V** соотвественно.
 2. Каждое слово получает три разных представления — как запрос, как ключ и как значение — что позволяет различать цели сопоставления (*что ищем*, *с чем сравниваем*, и *что извлекаем*).
3. Для каждого слова вычисляется степень внимания к каждому другому слову (включая само себя), на основе сопоставления его запроса с ключами всех слов последовательности.
4. Вычисления происходят по той же схеме, как и для общего механизма внимания: для каждого запроса с помощью скалярных произведений находятся соответствия с ключами, после чего значения агрегируются с использованием полученных весов. Отличие в том, что **Q**, **K**, **V** порождены из **одного и того же входа**.

# Multi-head attention

**Multi-head attention** — это расширение механизма self-attention, который позволяет улавливать одновременно разные типы зависимостей в последовательности.

***Зачем нужны несколько голов?***
С точки зрения анализа текста одна голова способна фокусироваться лишь на одном аспекте контекста, например, ближайших словах, синтаксических связях, семантическом сходстве и т.д. Однако для полноценного понимания текста модели часто нужно одновременно учитывать несколько таких аспектов. Multi-head attention позволяет создать несколько независимых attention-проекций (голов), каждая из которых обучается смотреть на текст по-своему.

**Принцип работы**
Одна голова использует единый набор векторов **Q**, **K**, **V**. Соответственно, при multi-head attention входные эмбеддинги проецируются в несколько таких наборов **Q**, **K**, **V** с помощью матриц весов для каждой головы:

$$
Q_i = X W_i^Q, \\
K_i = X W_i^K, \\
V_i = X W_i^V
$$


## Принцип работы

 1. В каждой голове self-attention используется свой набор проекций входных эмбеддингов $X$ в векторы $Q$, $K$, $V$:
 
	$$Q_i = X W_i^Q, \quad K_i = X W_i^K, \quad V_i = X W_i^V$$

	где $i = 1, \dots, h$, $h$ — число голов, а матрицы $W_i^Q, W_i^K, W_i^V$ имеют размерность $d_{model} \times d_k$.  
    
    Размерность каждой головы: 

	$$
	d_k = \frac{d_{model}}{h}
	$$

 2. Каждая голова вычисляет self-attention независимо:

	$$
	\text{Attention}(Q_i, K_i, V_i) = \text{softmax}\left(\frac{Q_i K_i^\top}{\sqrt{d_k}}\right) V_i
	$$

 3. Выходы всех голов конкатенируются:

	$$ 
	\text{Concat}(head_1, \dots, head_h) \in \mathbb{R}^{d_{model}}
	$$

    и затем проходят через финальную линейную трансформацию $W^O \in \mathbb{R}^{d_{model} \times d_{model}}$:
    
	$$
	\text{MultiHead}(Q,K,V) = \text{Concat}(head_1, \dots, head_h)\, W^O
	$$

Таким образом, для каждого токена получается новый вектор размерности $d_{model}$, содержащий информацию со всех голов.

# Трансформеры

Наконец, мы можем перейти к изучению **трансформеров** — архитектуры нейронных сетей, которые используют механизм внимания для обработки последовательностей.

## Общее устройство трансформера
Классическая модель трансформера состоит из двух блоков:

 - **энкодера**, который получает входную последовательность и строит репрезентацию его признаков;
 - **декодера**, который использует признаки, полученные энкодером, вместе с другими видами инпута для генерации целевой последовательности.

Оба блока могут использоваться как вместе, так и независимо друг от друга, исходя из задачи:

 - **encoder-only модели**: подходят для задач, где требуется интерпретация входных данных, например, в классификации или NER;
 - **decoder-only модели**: используются для генерации текста;
 - **encoder-decoder модели**: хороши для генеративных задач, где нужно полагаться на инпут, таких как перевод или суммаризация текста.

## Позиционное кодирование
Архитектура трансформеров не содержит рекуррентных или свёрточных компонентов, поэтому информация о порядке токенов в ней отсутствует. Чтобы модель учитывала позицию токенов, применяется **позиционное кодирование**.

Трансформеры используют специальную схему позиционного кодирования, при которой каждая позиция в последовательности сопоставляется с вектором. Таким образом, на выходе слоя позиционного кодирования получается матрица, где каждая строка представляет собой вектор токена, к которому добавлена информация о его позиции.

Ниже приведён пример матрицы, кодирующей только позиционную информацию:

<sub>Источник: [A Gentle Introduction to Positional Encoding in Transformer Models, Part 1](https://machinelearningmastery.com/a-gentle-introduction-to-positional-encoding-in-transformer-models-part-1/)</sub>

Разберём этот механизм подробнее. Предположим, у нас есть входная последовательность длины **L**, и нам нужно закодировать позицию **k** элемента в этой последовательности. Позиционное кодирование задается с помощью синусоидальных функций разной частоты:

$$
\begin{aligned}
P(k, 2i) = \sin\Bigg(\frac{k}{n^{2i/d}}\Bigg) \\
P(k, 2i+1) = \cos\Bigg(\frac{k}{n^{2i/d}}\Bigg)
\end{aligned}
$$

Здесь:
$k$ — позиция объекта в последовательности, $0 ≤ k < L$;
$d$ — размерность пространства эмбеддингов (выходная размерность)
$P(k,j)$ — функция позиционного кодирования, которая отображает позицию $k$ во входной последовательности в индекс $(k,j)$ в позиционной матрице;
$n$ — задаваемая константа, обычно равная $10000$;
$i$ — индекс частоты позиционного кодирования, $0 ≤ i < d/2$.  Каждое значение $i$ соответствует двум соседним столбцам эмбеддинга: один синус, один косинус.

Рассмотрим предожение *I am a robot* с параметрами `n = 100` и `d = 4`. Таблица ниже показывает матрицу позиционного кодирования для этой последовательности:

На выходе слой позиционного кодирования суммирует позиционный вектор с эмбеддингом слова и передает полученную матрицу последующим слоям модели.

## Энкодер

Энкодер обрабатывает входную последовательность и создаёт из неё наборов векторов, которые кодируют не только каждый элемент в данной последовательности, но и их взаимосвязи.

Энкодер состоит из стека идентичных слоёв (как правило, 6). Каждый слой состоит из двух подслоёв. Первый подслой представляет собой механизм multi-head attention, а второй — **полносвязную позиционную сеть** (position wise feed-forward network), применяемая идентично к каждой позиции токенов. Хотя подслой attention позволяет каждому токену учитывать информацию обо всех других токенах, он лишь смешивает эти представления. Подслой FFN, в свою очередь, нелинейно преобразует полученное представление каждого токена индивидуально, добавляя модели способность усиливать или подавлять определённые признаки и в целом замечать более сложные, нелинейные паттерны в данных, которые трудно уловить исключительно с помощью механизма внимания.

Оба подслоя используют остаточные связи (residual connection), после которых применяется нормализация слоя (layer normalization). Таким образом, выход каждого подслоя вычисляется как $x = \mathrm{LayerNorm}\big(x + \mathrm{Sublayer}(x)\big)$, что стабилизирует обучение и позволяет градиентам эффективно протекать через глубокую сеть. Чтобы такая схема работала, все подслои и слои эмбеддингов выдают представления одной размерности $d_{model} = 512$, что обеспечивает совместимость при сложении входа и выхода.

***Рассмотрим устройство подслоёв детальнее***:

 - Self-attention подслой: здесь запросы (Q), ключи (K) и значения (V) формируются из выходных данных предыдущего слоя энкодера (для первого слоя — из входных эмбеддингов). Это позволяет каждому токену пересчитать своё представление, взвешенно учитывая представления всех остальных токенов в последовательности.

FFN подслой: Эта сеть применяется независимо и идентично к каждой позиции. Она состоит из двух линейных преобразований с активацией ReLU посередине:

$$
\mathrm{FFN}(x) = \max\big(0,\, x W_1 + b_1\big) W_2 + b_2
$$

Здесь:
$x$ — вектор признаков одного токена (например, размерностью $d_{model} = 512$),
$W_1, b_1, W_2, b_2$ — обучаемые параметры.
Хотя линейные преобразования одинаковы для разных позициях, они используют разные параметры от слоя к слою. Вход и выход имеют размерность $d_{model} = 512$, внутренний слой — $d_{ff} = 2048$.

## Декодер

Декодер предназначен для генерации выходной последовательности токен за токеном. Как и в случае с энкодером, стек декодера состоит из 6 одинаковых слоёв. Однако, в отличие от энкодера, каждый слой декодера содержит три подслоя:

 - **Masked multi-head attention**: позволяет токену учитывать только предыдущие токены в генерируемой последовательности. Маска накладывается на матрицу внимания так, чтобы позиции справа (будущие токены) не участвовали в вычислениях. Это сохраняет авторегрессию. Как и в энкодере, запросы, ключи и значения (Q, K, V) формируются из выходов предыдущего слоя декодера (или из входных эмбеддингов на первом слое).

 - **Encoder–decoder cross-attention**: Этот подслой связывает декодер с выходными представлениями энкодера. Здесь: 
	 - запросы (Q) поступают из выхода маскированного self-attention подслоя декодера;
	 - ключи (K) и значения (V) берутся из выхода последнего слоя энкодера.

	Этот механизм позволяет декодеру на каждом шаге смотреть на всю входную последовательность и извлекать нужную информацию для генерации следующего токена.

 - **Полносвязная позиционная сеть (FFN)**: аналогична той, что используется в энкодере.

Как и в энкодере, каждый из трёх подслоёв декодера оборачивается в остаточную связь с последующей нормализацией. Входные эмбеддинги декодера суммируются с позиционным кодированием и подаются со сдвигом на один токен, а маскирование гарантирует, что предсказание токена в позиции $i$ зависит только от уже сгенерированных элементов последовательности.

# Предобучение и fine-tuning

Трансформеры обучают на колоссальном объёме текстовых данных. В идеальной картине мира мы хотели бы использовать хорошие размеченные датасеты, однако создание таких датасетов — крайне дорогое и трудоёмкое занятие. Из-за этого обучение трансформеров обычно делится на два этапа:

 - предобучение, при котором мы “скармливаем” модели множество неразмеченных данных для того, чтобы модель “усвоила” устройство языка на более фундаментальном уровне;
 - fine-tuning, то есть дообучение на небольшом размеченном датасете под конкретную задачу.

## Encoder-only models

У трансформеров, состоящих только из блока энкодера, последовательность входных токенов преобразуется в аналогичное количество векторных представлений, которые затем могут быть преобразованы в выходные данные (например, для задачи классификации).

Чтобы лучше понять принцип работы данной архитектуры, рассмотрим модель **BERT** (Bidirectional Encoder Representations from Transformers). BERT проходит этап предобучения на больших текстовых корпусах с помощью задачи **маскированного языкового моделирования** (Masked Language Modeling). Входной текст, в котором случайные токены заменены на специальный токен `<mask>`, подаётся в трансформер-энкодер. Задача модели — предсказать исходные маскированные токены.

Возьмём такую последовательность: [`Я`, `люблю`, `этот`, `красный`, `автомобиль`]. В ней случайным образом маскируется токен `люблю`. Модель получает на вход [`Я`, `<mask>`, `этот`, `красный`, `автомобиль`] и обучается предсказывать исходное слово `люблю`, минимизируя лосс-функцию (а именно кросс-энтропию) между предсказанием и истинным значением.

Поскольку в энкодере нет ограничений на механизм внимания, каждый токен может видеть все остальные токены в последовательности. Это позволяет BERT учитывать контекст как слева, так и справа от маскированного слова, поэтому, как следует из его названия, это двунаправленная модель.

После предобучения модель BERT может быть дообучена для решения конкретных задач: классификации текста, анализа тональности, извлечения сущностей NER, QA-систем и др.
На этапе fine-tuning к предобученному энкодеру добавляются **task-specific слои** — например, линейный классификатор поверх векторного представления токена специального `<cls>`, агрегирующий информацию о всей последовательности. Эти новые слои инициализируются случайным образом, а веса самого BERT корректируются под задачу.

Обучение проводится на размеченных данных целевой задачи с минимизацией кросс-энтропии. При этом градиенты проходят через все слои модели, обновляя как параметры добавленного классификатора, так и веса предобученного BERT.

## Encoder-decoder models

Как уже упоминалось в предыдущем разделе, энкодер трансформера преобразует последовательность входных токенов в такое же количество выходных представлений. Это означает, что в режиме encoder-only модель не может генерировать последовательности произвольной длины, как это требуется, например, в машинном переводе. Изначально предложенная для этой задачи архитектура трансформера включает в себя и декодер, который авторегрессионно (токен за токеном) предсказывает целевую последовательность произвольной длины. Это предсказание строится на двух источниках, которые обсуждались ранее:

 1. Выход энкодера: с помощью механизма multi-head attention в декодере токены получают доступ ко всем входным токенам, обработанным энкодером. 
 2. Уже сгенерированный выход декодера: благодаря маскированию в attention декодера гарантируется, что при предсказании следующего токена модель может обращаться только к предыдущим и текущему токенам целевой последовательности.

Среди трансформеров с encoder-decoder архитектурой можно выделить модели **BART** и **T5**. Обе обучаются на крупных текстовых корпусах и ставят задачу восстановления исходного текста, но разными способами:
 - BART использует различные виды искажения входного текста (маскирование, удаление, перестановка токенов);
 - T5 фокусируется на унификации разнородных задач в формате **text-to-text**: вместо того чтобы создавать для каждой задачи (классификация, NER, др.) свою специализированную архитектуру головы модели, все они сводятся к задаче генерации текста.

Рассмотрим процесс предобучения и fine-tuning на примере T5. В первом случае применяется задача **предсказания последовательных отрезков** (span prediction), при которой в исходном тексте случайные непрерывные фрагменты заменяются на специальные токены-метки.
Возьмём предложение *I love this car*. Здесь токены `love`, `red`, `car` заменяются случайными токенами, и так как `red` и `car` идут друг за другом, на их место ставится один токен `<Y>`. Таким образом, входной последовательностью энкодера является цепочка `I`, `<X>`, `this`, `<Y>`, а целевой последовательностью декодера — `<X>`, `love`, `<Y>`, `red`, `car`, `<Z>` (`<Z>` — токен, обозначающий конец предложения). Декодер обучается авторегрессионно: он предсказывает каждый следующий токен, имея доступ только к предыдущим.

Что касается fine-tuning, то, как и BERT, T5 требует дообучения на данных конкретной задачи. Однако в случае T5 есть некоторые особенности:

 - Вход всегда включает описание задачи. Допустим, у нас есть текст, который мы хотим суммаризировать. В энкодер модели мы должны подать как сам текст, так и цель задания. 
 - Декодер позволяет генерировать ответы произвольной длины.
 - Создавать дополнительные слои не требуются.

## Decoder-Only models

В этих трансформерах используется только декодер из оригинальной encoder-decoder схемы. Помимо блока энкодера убирается подслой encoder-decoder cross-attention в декодере. В настоящее время эта архитектура используется в больших языковых моделях, обучающихся на масштабных текстовых корпусах.

Давайте вспомним про особенность работы декодера и разберём принципы обучения и fine-tuning на примере GPT (generative pre-trained transformer). Decoder-only трансформеры обучаются таким образом, что модель предсказывает следующий токен по предыдущим. Во время обучения входная последовательность подаётся в модель целиком, а целевая последовательность представляет собой ту же строку, но сдвинутую на один токен вперёд. Таким образом, модель учится восстанавливать токен $i$ на основе всех токенов от начала последовательности до позиции $i-1$. Маскированный механизм self-attention гарантирует, что каждый токен может видеть только свои прошлые позиции: обращение к будущим токенам исключено, поскольку по определению авторегрессивности они ещё не сгенерированы.

После предобучения на больших неразмеченных корпусах языковые модели семейства GPT адаптируются под конкретные downstream-задачи с помощью fine-tuning. В классическом подходе (как в раннем GPT с ~100 млн параметрами) модель дообучается на размеченных данных выбранной задачи. Во время fine-tuning параметры модели продолжают обновляться с помощью градиентных шагов, что позволяет ей подстроиться к специфике новой задачи.

Тем не менее, такой подход имеет важный недостаток: fine-tuning вычислительно дорог, так как требует хранения копий модели, пересчёта градиентов и повторного обучения для каждой задачи. Поэтому по мере роста масштабов моделей стали появляться альтернативы.

Появление GPT-2 с 1.5 млрд параметров, обученного на 40 ГБ текста, показало, что крупная предобученная языковая модель может демонстрировать хорошие результаты на множестве задач без дополнительного обучения. Вместо fine-tuning модель могла выполнять новые задачи в zero-shot режиме, используя только текстовый запрос без изменения своих весов.

> Zero-shot — метод машинного обучения, позволяющий модели решать задачу или распознавать объект, с которым она никогда ранее не сталкивалась во время обучения, опираясь только на свои общие знания и понимание контекста.

Эта тенденция усилилась с выходом GPT-3, где был систематизирован подход, получивший название **in-context learning**. В этом режиме модель решает задачу, исходя лишь из входного контекста (промпта), в который можно включать:

 - описание задачи;
 - один пример, демонстрирующий желаемый результат (one-shot);
 - несколько примеров (few-shot).
